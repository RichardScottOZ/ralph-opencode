## 🧠 What is Ralph Wiggum?

Ralph Wiggum is an autonomous development technique created by **Geoffrey Huntley**. The concept adapts well to OpenCode's agent-based workflow.

### Philosophy

> _"The technique is **deterministically bad in an undeterministic world**."_

- When Ralph fails, you don't blame the tools — **you tune the prompts**
- Failures are predictable and informative
- Success requires faith in eventual consistency
- Each failure teaches you what "signs" (guardrails) to add

### The Playground Metaphor

From Huntley:

> _"Ralph is very good at making playgrounds, but he comes home bruised because he fell off the slide, so one then tunes Ralph by adding a sign next to the slide saying 'SLIDE DOWN, DON'T JUMP, LOOK AROUND,' and Ralph is more likely to look and see the sign."_

Eventually, the prompt has enough guardrails that Ralph works reliably.

## 🔧 How to Set Up

### Prerequisites

| Requirement | Description |
|-------------|-------------|
| **OpenCode** | Already installed and configured |
| **Git** | For state tracking and memory |

### Step 1: Install OpenCode

If you haven't already installed OpenCode:

```bash
# YOLO install
curl -fsSL https://opencode.ai/install | bash

# Or with package managers
npm i -g opencode-ai@latest
brew install anomalyco/tap/opencode  # macOS and Linux

# Verify installation
opencode --version
```

### Step 2: Clone this Repository

```bash
git clone https://github.com/RichardScottOZ/ralph-opencode.git
cd ralph-opencode
```

### Step 3: Set Up a New Project

```bash
# Copy the ralph-opencode setup to your project
./setup-ralph.sh my-project

# Or manually:
mkdir my-project
cd my-project
git init
mkdir -p .opencode/agent
cp -r /path/to/ralph-opencode/.opencode/agent/* .opencode/agent/
cp /path/to/ralph-opencode/templates/* .
```

### Project Structure After Setup

```
my-project/
├── .git/                          # Git repo (required)
├── .opencode/
│   └── agent/
│       ├── ralph-clarify.md       # Phase 1: Requirements discovery
│       └── ralph-plan.md          # Phase 2: Generate execution files
├── PROMPT.md                      # Ralph's instructions (generated by plan)
├── TODO.md                        # Task checklist (generated by plan)
├── clarify-session.md             # Requirements (from interview)
└── src/                           # Your code (created during execution)
```

## 📋 Phase 1: Clarify

The clarify phase uses interactive questioning to gather **40-70 questions** covering all aspects of the project.

### Why This Matters

> _"The loop pressure overrides the natural tendency to stop asking after 3-5 questions."_

### Question Categories

| Category | Questions to Cover |
|----------|-------------------|
| **Core Requirements** | What must this do? What's MVP? What's out of scope? |
| **Users & Context** | Who uses this? What's their skill level? What constraints exist? |
| **Technical Choices** | Language? Framework? Database? Dependencies? |
| **Integration Points** | What systems does this connect to? What data flows in/out? |
| **Edge Cases** | What happens when things fail? Boundary conditions? |
| **Quality Attributes** | Performance requirements? Security considerations? |
| **Existing Patterns** | How do similar things work in this codebase? Conventions? |
| **Preferences** | Strong opinions on approach? Tradeoffs? |

### Running the Clarify Phase

```bash
# Start OpenCode
opencode

# In the OpenCode session:
# 1. Press Tab to cycle to ralph-clarify agent
# OR
# 2. Type: @ralph-clarify to invoke the agent

# In the chat, describe your project:
# "I want to build a REST API for task management"

# The agent will ask you 40-70 questions
# Answer them thoroughly
# Results are saved to clarify-session.md
```

### Output: `clarify-session.md`

```markdown
# Discovery: Task Management API

Started: 2024-01-10

## Questions Asked
1. What authentication method? → JWT
2. What database? → PostgreSQL
3. ...

## Answers Received
- Authentication: JWT with refresh tokens
- Database: PostgreSQL with Prisma ORM
- ...

## Emerging Requirements
- Must support 1000 concurrent users
- API must be RESTful with OpenAPI spec
- All endpoints require authentication except /health
- ...
```

Convert the clarify session into actionable instructions.

# It will create PROMPT.md and TODO.md

### Generated Files

**PROMPT.md** — Execution instructions with guardrails  
**TODO.md** — Prioritized task checklist with HARD STOP checkpoints

## 🚀 Phase 3: Execute

Work through the tasks using OpenCode's build agent.

### How It Works

```bash
# Start OpenCode in your project
opencode

# Switch to the build agent (press Tab if needed)
# The build agent is the default agent

# The build agent will:
# 1. Read PROMPT.md for instructions
# 2. Read TODO.md for tasks
# 3. Pick the highest priority incomplete task
# 4. Implement it
# 5. Run tests
# 6. Mark it complete in TODO.md
# 7. Commit changes
# 8. Move to next task
```

### What Happens During Execution

```
Session 1: Build agent reads PROMPT.md → Picks Task 1 → Implements → Commits
     ↓
Session 2: Build agent reads PROMPT.md → Sees Task 1 done → Picks Task 2 → Implements
     ↓
Session 3: ...
     ↓
Session N: All tasks done → Agent outputs "DONE"
```

Each iteration:
- Sees the same `PROMPT.md`
- But files have changed (previous work persists)
- Git history shows progress
- `TODO.md` reflects completed tasks

### Manual Execution Loop (Advanced)

For more control, you can manually guide the agent through each task:

1. Open OpenCode in your project
2. Reference PROMPT.md in your messages
3. Ask the build agent to pick the next task from TODO.md
4. Review and commit after each task
5. Repeat until all tasks are complete

## 📄 Templates

### Minimal PROMPT.md (Start Here)

```markdown
# PROMPT.md

Build [WHAT YOU'RE BUILDING].

Requirements:
- [Requirement 1]
- [Requirement 2]
- [Requirement 3]

Track progress in TODO.md. Commit after each completed item.

When all requirements are implemented and tests pass, output: DONE
```

### PROMPT.md with Guardrails

```markdown
# PROMPT.md

## Task
[Description of what to build]

## Requirements
Read clarify-session.md for full requirements.

## Instructions
1. Read TODO.md for current tasks
2. Pick highest priority incomplete task
3. Read any files before editing them
4. Implement the task
5. Run tests
6. If tests fail, fix before continuing
7. Mark complete in TODO.md
8. Commit with clear message
9. Repeat until all tasks done

## Signs (Guardrails)
- Always read before editing
- Never skip failing tests
- Don't refactor unrelated code
- Keep commits focused
- Update TODO.md immediately after completing tasks

## Completion
When TODO.md shows all tasks complete and tests pass, output: DONE
```

### TODO.md Template

```markdown
# TODO

## Critical (Must Have)
- [ ] Task 1
- [ ] Task 2
- [ ] **HARD STOP** - Verify core flow works end-to-end

## Important (Should Have)
- [ ] Task 3
- [ ] Task 4

## Nice to Have
- [ ] Task 5
- [ ] Task 6

---
## Completed
- [x] Example completed task
```

## 🔄 Differences from Kiro CLI

This implementation adapts the original Ralph Wiggum workflow from Kiro CLI to OpenCode:

| Feature | Kiro CLI (Original) | OpenCode (This Repo) |
|---------|---------------------|----------------------|
| **Agent System** | `.kiro/agents/*.yaml` | `.opencode/agent/*.md` |
| **Configuration** | YAML with tools list | Markdown with frontmatter |
| **Agent Switching** | `kiro-cli chat --agent` | Tab key or @mention |
| **Execution** | Bash loop with `--mode script` | Interactive with build agent |
| **Completion** | Bash grep for "DONE" | Manual monitoring or agent output |
| **Loop Control** | Manual bash loop | Session-based iterations |

### Key Adaptations

1. **Agents as Markdown**: OpenCode uses markdown files with frontmatter instead of YAML
2. **Interactive Flow**: OpenCode is designed for interactive sessions, not scripted loops
3. **Agent Switching**: Use Tab key to cycle between agents or @mention to invoke
4. **Build Agent**: Use OpenCode's built-in build agent for execution instead of scripted loop
5. **Session-Based**: Work happens in interactive sessions rather than automated bash loops

## 🛠️ Troubleshooting

### Agent Doesn't Switch

**Problem**: Can't switch to ralph-clarify or ralph-plan

**Solutions**:
- Ensure agent files exist in `.opencode/agent/`
- Check that markdown files have proper frontmatter
- Restart OpenCode to reload agents
- Try @mentioning the agent: `@ralph-clarify`

### Agent Doesn't Follow Instructions

**Problem**: Agent skips tasks or doesn't follow PROMPT.md

**Solutions**:
- Add more specific guardrails to PROMPT.md
- Break down large tasks into smaller, clearer subtasks
- Reference PROMPT.md explicitly in your messages
- Review completed work and add "signs" for common failures

### Tasks Not Being Completed

**Problem**: Build agent doesn't mark tasks complete in TODO.md

**Solutions**:
- Explicitly remind the agent to update TODO.md
- Add this to PROMPT.md guardrails
- Manually verify and update TODO.md periodically

### OpenCode Installation Issues

**Problem**: OpenCode not working after installation

**Solutions**:
```bash
# Re-install via preferred method
npm i -g opencode-ai@latest

# Or use brew
brew install anomalyco/tap/opencode

# Verify
opencode --version
```

## 💡 Philosophy Recap

Ralph Wiggum is about:

1. **Iterative Refinement**: Each failure teaches you how to tune the prompts
2. **Guardrails**: Add "signs" to prevent repeated failures
3. **Exhaustive Requirements**: Thorough clarification prevents execution problems
4. **Vertical Slices**: Build one complete flow before expanding
5. **Git as Memory**: Every iteration commits, creating a trail of progress
6. **Trust the Process**: Have faith that eventual consistency works

The workflow transforms chaotic AI behavior into deterministic progress through structured prompts and clear guardrails.
